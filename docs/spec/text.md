# Spec: text

Milestone: M3.

## Command

| Command | Undo | Effect |
| --- | --- | --- |
| `shape.add_text <x> <y> <height> <font> <text> [@color]` | delete | Add text as outlines, its first baseline starting at (x, y). |

- `<font>` is a font family name looked up among the fonts installed on
  the system (case-insensitive, regular weight and upright style preferred),
  or a path to a `.ttf`, `.otf` or `.ttc` file (any argument containing a
  path separator or ending in one of those extensions). An unknown family
  fails with "font `<name>` is not installed" and lists nothing else.
- `<height>` is the height of capital letters in mm (0.1–1000): the font is
  scaled so its cap height (from the font's OS/2 table; when missing, the
  height of the `H` outline; when that is missing too, 70 % of the em) is
  `height`.
- `<text>` is one argument (quote it). A line break in the text (typed in
  the text window, or a newline inside a quoted argument) starts a
  new line, one line spacing (ascender − descender + line gap, scaled)
  further down. Empty text, or text with no visible outline (only spaces),
  fails with "nothing to draw".
- Characters are placed by their advance widths plus the font's `kern`
  table pair adjustments. There is no complex shaping (ligatures, GPOS
  kerning, right-to-left reordering); characters missing from the font are
  drawn as the font's missing-glyph box.
- The result is one `path` shape: every glyph contour is a closed subpath,
  so letters with counters (O, A, e) have holes under the even-odd rule.
  TrueType quadratic curves are raised to cubics exactly; CFF cubics are
  kept. The local origin of the path is the first baseline's start, with
  the shape's transform a translation to (x, y), so moving, scaling and
  rotating work as for any shape.

## Text is converted to outlines when created

Trade-off (own design): LaserCraft stores text as its outline path, not as
editable text with a font reference.

- For: a project looks and cuts the same on every machine, whether or not
  the font is installed; files hold no font data or font names that must
  resolve; the outline is deterministic for a given font file, so tests and
  goldens can rely on it; every path tool (nodes, booleans, offset) works
  on text right away.
- Against: changing the words or font means deleting and re-adding the
  text (undo makes this cheap). Editable text objects may come later as a
  new geometry kind (an additive format change) that keeps the outline as a
  fallback.

## Text tool

- Ctrl+T (or Tools → Text) switches the canvas to the text tool. Clicking
  the canvas opens a small window at that point with the text, font family
  (default: the first of "DejaVu Sans", "Liberation Sans", "Arial",
  "Helvetica" that is installed, else the first installed family) and
  height (default 10 mm); OK runs one `shape.add_text` on the current
  color. Closing the window adds nothing.

## Determinism and tests

- Given the same font file, the same arguments always give the same path,
  bit for bit.
- Tests use `examples/fixtures/lctest.ttf`, a tiny font drawn for LaserCraft
  (own work, GPL-3.0-or-later like the rest of the repository; generated by
  `examples/fixtures/make_lctest_font.py`). It covers space and
  `A C H I L O T`, has quadratic curves, a counter (`O`, `A`) and one kern
  pair (`L`,`T`). Tests that look fonts up by family name skip their
  assertions, saying so, when the machine has no fonts installed.
